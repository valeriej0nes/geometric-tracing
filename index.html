How Geometric Tracing Works

Geometric Tracing converts an image into explicit mathematical geometry. The pipeline begins with a discrete image, extracts its structural edges, reduces those edges to one-pixel-wide centerlines, interprets the result as a graph, and finally converts the geometry into either piecewise linear equations or smooth parametric spline curves.

Image as a Mathematical Object

A digital image can be viewed mathematically as a discrete function defined on a rectangular grid of pixels.

For a color image, each pixel contains three intensity values:

\[ F(x,y)=\big(R(x,y),G(x,y),B(x,y)\big) \]

where \(x,y\) are pixel coordinates, and \(R,G,B\) are red, green and blue channel intensities. Thus, an RGB image is no more than a vector-valued discrete field.

In continuous mathematics, one often imagines an idealized image as a continuous function:

\[ F:\mathbb{R}^2\to\mathbb{R}^3 \]

but an actual digital image only samples this function on a finite lattice:

\[ (x,y)\in\mathbb{Z}^2 \]

This distinction matters because operations such as differentiation and curve fitting must ultimately be approximated numerically on a discrete grid.

After grayscale conversion, the image becomes a scalar field:

\[ I(x,y) \]

which assigns a single intensity value to each pixel.

Grayscale Conversion

Edge detection is fundamentally based on intensity variation, so the RGB image is first converted into a scalar luminance image.

Here we use the standard luminance weighting:

\[ I(x,y)=0.299R(x,y)+0.587G(x,y)+0.114B(x,y) \]

These coefficients reflect human visual sensitivity, where the eye is more sensitive to green light than blue light.

The result is a scalar intensity field:

\[ I:\mathbb{Z}^2\to\mathbb{R} \]

This is important mathematically because scalar fields can be differentiated. Gradients, directional derivatives, and edge detection are all defined naturally on scalar intensity functions.

Gaussian Smoothing

Real images contain noise, texture, compression artifacts and pixel-level fluctuations. Direct differentiation of noisy data produces unstable gradients.

Before edge detection, the image is smoothed with a Gaussian filter. The continuous 2D Gaussian kernel is:

\[ G_\sigma(x,y)=\frac{1}{2\pi\sigma^2}\exp\left(-\frac{x^2+y^2}{2\sigma^2}\right) \]

The smoothed image is obtained by convolution:

\[ I_s=G_\sigma * I \]

where \(*\) denotes convolution.

We use kernel size \(5\times5\) and standard deviation \(\sigma=1.4\).

Gaussian smoothing acts as a low-pass filter. High-frequency variations, such as noise and fine texture, are attenuated, while larger geometric structures remain. This stabilization is essential because numerical differentiation amplifies high-frequency noise.

Image Gradients

Edges occur where intensity changes rapidly. To measure local intensity variation, partial derivatives are computed:

\[ I_x=\frac{\partial I}{\partial x},\qquad I_y=\frac{\partial I}{\partial y} \]

Together these form the image gradient:

\[ \nabla I=\left(I_x,I_y\right) \]

The gradient vector points in the direction of maximal intensity increase. The Euclidean gradient magnitude is:

\[ |\nabla I|=\sqrt{I_x^2+I_y^2} \]

Large gradient magnitude indicates a likely edge. In this case however, gradients are computed inside OpenCV's Canny implementation using its default \(3\times3\) Sobel derivative aperture, and the thresholding step uses the default L1-style magnitude:

\[ M_1(x,y)=|I_x(x,y)|+|I_y(x,y)| \]

This differs slightly from the Euclidean L2 magnitude above, but it serves the same purpose and assigns larger values to pixels where intensity changes sharply.

The gradient direction is:

\[ \theta=\operatorname{atan2}(I_y,I_x) \]

which gives the orientation of the edge normal. Because images are discrete, the derivatives are not symbolic derivatives, they are finite-difference approximations. Here, that approximation is specifically OpenCV's default Sobel operator inside cv.Canny.

Canny Edge Detection

The app uses the Canny edge detector, a multi-stage algorithm designed to produce thin, stable, well-localized edges.

Gradient Magnitude

The smoothed image gradient is computed using OpenCV's default \(3\times3\) Sobel derivative filters:

\[ I_x \approx S_x * I_s,\qquad I_y \approx S_y * I_s \]

With the current code, Canny thresholds the default L1 gradient magnitude:

\[ M_1(x,y)=|I_x(x,y)|+|I_y(x,y)| \]

Pixels with large magnitude correspond to strong local intensity transitions.

Non-Maximum Suppression

Edges should be thin curves, not thick bands. For each pixel, the algorithm compares the gradient magnitude with neighboring pixels along the gradient direction. If the pixel is not a local maximum, it is suppressed:

\[ |\nabla I(x,y)| < \text{neighbor maximum}\quad\Rightarrow\quad 0 \]

This reduces broad gradient regions to approximately one-pixel-wide edge candidates.

Double Thresholding

Two thresholds are applied to the Canny gradient response: lower threshold \(50\) and upper threshold \(150\).

  • strong edges: \(M_1\ge150\)
  • weak edges: \(50\le M_1<150\)
  • non-edges: \(M_1<50\)

Hysteresis

Weak edges are retained only if connected to strong edges. This suppresses isolated noise responses while preserving continuous contours.

The final edge image is therefore a binary subset of the pixel grid:

\[ E\subseteq\mathbb{Z}^2 \]

where each element of \(E\) is classified as an edge pixel. OpenCV stores this result as an 8-bit image whose pixels are either \(0\) or \(255\). We then map values above \(80\) to \(1\), so Canny's white edge pixels become binary foreground pixels and black pixels become background.

Binary Edge Image

After edge detection, the image is represented as a binary function:

\[ B(x,y)\in\{0,1\} \]

where \(B(x,y)=1\) means the pixel belongs to an edge, and \(B(x,y)=0\) means background.

Equivalently, the edge image may be viewed as a set:

\[ A=\{(x,y):B(x,y)=1\} \]

In code, this is a typed array where each pixel is either \(0\) or \(1\). This set-theoretic interpretation is important because later stages operate on geometry rather than color intensities.

Skeletonization / Medial Axis

The edge image still contains curves with thickness. To extract a cleaner geometric representation, we perform skeletonization

Conceptually, the skeleton is a topology-preserving thinning of the binary set \(A\).

The idealized geometric intuition comes from the medial axis, points lying at the centers of maximal disks contained within the shape. Equivalently, skeleton points are approximately equidistant from nearby boundaries.

The implementation uses the Zhang-Suen thinning algorithm. It iteratively removes eligible foreground pixels in two sub-iterations. For each foreground pixel \(p\), the algorithm examines its 8-neighborhood:

\[ (p_2,p_3,p_4,p_5,p_6,p_7,p_8,p_9) \]

It computes the neighbor count:

\[ N(p)=\sum_{i=2}^{9}p_i \]

and the number of \(0\to1\) transitions around the ordered neighborhood:

\[ S(p)=\#\{i:p_i=0,\;p_{i+1}=1\} \]

Pixels are removed only when conditions such as \(2\le N(p)\le6\) and \(S(p)=1\) hold, along with pass-specific connectivity constraints. These tests thin strokes while preserving branch connectivity.

The result is a one-pixel-wide centerline representation of the geometry.

Skeleton as a Graph

The skeleton image is interpreted as a graph:

\[ G=(V,E) \]

where \(V\) is the set of skeleton pixels, and \(E\) connects neighboring pixels using 8-neighbor connectivity. Thus, each pixel may connect horizontally, vertically, or diagonally.

For a node \(v\in V\), the degree is the number of neighboring skeleton pixels connected to it.

  • endpoint: \(\deg(v)=1\)
  • chain point: \(\deg(v)=2\)
  • junction: \(\deg(v)\ge3\)

Paths are traced through sequences of chain points between endpoints and junctions. This converts the skeleton into ordered geometric paths rather than isolated pixels.

Method A: Piecewise Linear Approximation

Each traced path is represented as an ordered sequence of points:

\[ P=(p_0,p_1,\dots,p_n) \]

where:

\[ p_i=(x_i,y_i) \]

The goal is to simplify the path while preserving its geometry. We use a tolerance-based simplification similar to the Ramer-Douglas-Peucker algorithm.

A point \(p_i\) may be removed if its perpendicular distance to the approximating segment is sufficiently small:

\[ d(p_i,\text{line segment})<\varepsilon \]

where \(\varepsilon\) is a geometric tolerance.

The resulting simplified polyline consists of straight segments between retained vertices. For a segment joining:

\[ (x_1,y_1)\quad\text{and}\quad(x_2,y_2) \]

the slope is:

\[ m=\frac{y_2-y_1}{x_2-x_1} \]

and the intercept is:

\[ b=y_1-mx_1 \]

giving the Cartesian equation:

\[ y=mx+b \]

For vertical segments:

\[ x=c \]

This method produces a piecewise linear approximation of the image geometry. Thus straight boundaries are represented exactly, while curved boundaries are approximated by many small linear segments.

Method B: Parametric B-Spline Approximation

Many shapes are inherently curved and cannot be represented compactly by straight segments.

Instead of expressing geometry as:

\[ y=f(x) \]

we use a parametric representation:

\[ x=x(t),\qquad y=y(t),\qquad t\in[0,1] \]

A parametric spline curve is controlled by a sequence of ordered skeleton control points:

\[ P_0,P_1,\dots,P_n,\qquad P_i=(x_i,y_i) \]

In a classical B-spline model, the curve is written as:

\[ C(t)=\sum_i N_{i,k}(t)P_i \]

where \(N_{i,k}(t)\) are B-spline basis functions, \(k\) is the spline degree, and \(P_i\) are control points. This is the mathematical model the interface is named after.

The current browser implementation uses a lightweight Catmull-Rom spline interpolation through the ordered skeleton control points. This keeps the app fully static and avoids shipping a large numerical fitting library. For a local segment with neighboring control points \(P_{i-1},P_i,P_{i+1},P_{i+2}\), the sampled curve is:

\[ C_i(u)=\frac12\left( 2P_i+ (-P_{i-1}+P_{i+1})u+ (2P_{i-1}-5P_i+4P_{i+1}-P_{i+2})u^2+ (-P_{i-1}+3P_i-3P_{i+1}+P_{i+2})u^3 \right) \]

where \(u\in[0,1]\) is the local segment parameter. The app samples these parametric segments to produce the plotted smooth curve.

The important mathematical property is that the output is parametric: it does not require the contour to be a single-valued function \(y=f(x)\). Loops, vertical tangents, and curved boundaries can be represented by \(x(t)\) and \(y(t)\) together.

Coordinate System

Image coordinates and Cartesian coordinates are usually oriented differently. In image processing, \(x\) increases to the right and \(y\) increases downward. In standard mathematical plotting, \(x\) increases to the right and \(y\) increases upward.

We convert traced pixel coordinates into Cartesian-style plot coordinates before computing equations:

\[ X=x,\qquad Y=-y \]

This flips the vertical axis into the conventional mathematical orientation. Thus the equations shown describe the plotted coordinates \((X,Y)\), not the raw canvas coordinates \((x,y)\).
